# 换设备：可复用源码，不是整机无缝备份

**结论：不能仅凭 `git clone` 并补上模型配置，就宣称与当前工作机完整无缝一致。**

本仓库保存核心集成、可移植模板和部分已部署 dashboard 源补丁。它故意不保存私人会话、认证、论文和运行数据，也没有打包工作机上全部外部工具、技能与第三方包内的本地修改。

## 已核对的一致部分

2026-10-13 与当前 Linux 工作机做了只读比对：

- Pi 固定版本为 `1.0.0`；配置模板中的 **13 个 npm 扩展来源与本机实际安装版本一致**。
- 自有 `integration/src/` 的三个模块与本机一致。
- `extensions/undo-last.ts` 与本机批准的忙碌立即拒绝版本一致。
- Dashboard 固定源码上的两个补丁可检查、应用，发布的 **17 个前端 + 3 个 native bridge 文件哈希匹配**。

这些检查不证明整套运行环境相同。同一 npm 包版本也可能有本地源码修改或不同的传递依赖；本仓库不是所有依赖的完整锁定镜像。

## 除模型外，仍需补齐什么

| 能力 / 状态 | 克隆默认得到什么 | 新设备仍需做什么 |
|---|---|---|
| 核心科研工具 | 13 个固定 npm 来源、自有集成和角色模板 | 运行安装脚本；核对插件加载和本地工具可执行性 |
| Dashboard / 撤回编辑 | 固定上游、前端与 native bridge 补丁 | 安装匹配的 pnpm、构建、配置 bridge、启动并验收；不是克隆后自动运行 |
| Dashboard 其他定制 | 没有完整收录工作机所有修补 | 工作机另有 provider/context/scanner 等源差异；不得认为两个补丁覆盖全部 |
| Dashboard 插件 / KB | 包来源参考，不复制本机启用状态 | 本机另有四个插件 bridge、KB 加载及配置；需要单独配置和验收 |
| 外部技能 / ARIS | 薄 wrapper，不是技能全集 | 本机另有 108 个外部技能目录；按其上游安装并核对必要 canonical 文件 |
| 子代理运行细节 | 固定 npm 版本与通用角色模板 | 本机有嵌套任务路由本地修改、更多 thinking 覆盖及 compaction 参数，未作为完整补丁发布 |
| 选模路由与验收历史 | 脱敏原则性指南 | 本机 policy/history 模块与实际记录未发布，不能恢复原自动选模行为或历史 |
| 网页模型 | 专用浏览器入口和可选 MCP 模板 | 安装 Chrome、配置桌面/路径、本人登录，核验网页实际模型，按任务配置文件授权根 |
| SSH / Slurm | 角色约束、可选上游来源 | 配置自己的 SSH alias/密钥、分区/资源/时长/环境；不要未经授权提交作业 |
| agy / LaTeX / 检索辅助 | 可选适配说明 | 单独安装所需 CLI/TeX/辅助程序并认证；这些不由模型配置解决 |
| 长期记忆 / KB 检索 | 相关 npm 扩展来源 | 辅助可执行程序、知识源和索引另行准备；扩展安装不等于检索可用 |
| 私人会话、论文、原始结果 | **不在仓库中** | 如需续接，另做加密点对点迁移，重映射项目路径；不要上传到 GitHub |
| 服务与远程访问 | 可选 service 模板 | 配置本机 systemd/端口/HTTPS 或 SSH 转发；clone 不会复制服务状态 |

模型相关的 provider UI/context 定制也没有全部发布；即使自己填好模型账号，也不能推定新 dashboard 的行为与当前设备完全相同。

## 首次安装检查与修正

远端 fresh clone 的离线测试28/28通过，旧安装脚本退出0且Pi版本为1.0.0；但实际13个扩展manifest均不存在，**不能将该退出码算作扩展安装成功**。Pi 1.0.0的 `update --extensions` 跳过精确固定版本；本轮隔离检查还禁用了Pi自动网络活动，两项条件均不适合用更新命令完成首次安装。

安装脚本已改为显式安装固定npm来源，保留Pi的受管目录与 `--legacy-peer-deps` 策略，并逐个核对包名和版本、保护原settings的资源过滤。`--check-only` 只检查，不下载：

```bash
node scripts/install-packages.mjs /absolute/path/to/isolated-agent --check-only
```

## 浏览器入口修正

迁移核验发现，原模板的 `chrome-devtools-mcp/build/src/index.js` 是库入口：执行退出 0，但不回复 MCP `initialize`。固定版本 `1.10.1` 的真正入口是：

```text
chrome-devtools-mcp/build/src/bin/chrome-devtools-mcp.js
```

当前模板已修正，并补充契约检查。文件上传权限只按任务授予所需目录；不要使用无限制根，也不要复制文件绕过工具拒绝。

## 推荐新机验收顺序

1. 先用 Linux + Node ≥22.19、Git、npm、Python3 和 Bash；本次没有验证 Windows/macOS 原生安装。
2. 克隆 **main 最新提交**，执行离线测试/语法/发布检查与 install dry-run。`v0.1.0` 保留初始快照，后续图片和入口修正不重写该标签。
3. 用新的 `PI_RESEARCH_AGENT_DIR` 安装核心依赖，确认不会覆盖已有配置。
4. 配好模型后做一个不含私有材料的小任务，核对扩展、子代理身份与输出；不要只检查目录存在。
5. 按需要配置 dashboard、浏览器、ARIS、agy、SSH 和调度器，再各自做小型验收。
6. 如果需要续接已有研究，最后私下迁移会话/记忆/论文/输入与结果目录，核对路径与哈希。哈希只能确认数据一致，不证明科研结论。

## 验证边界

本轮验证结果：

| 检查 | 结果 |
|---|---|
| 远端 main 全新克隆、离线测试 | 28/28 通过；克隆工作树保持干净 |
| 原安装脚本隔离执行 | 命令退出 0，Pi 1.0.0 安装成功；**13 个扩展缺失，整套安装未通过** |
| 首次安装修正的离线测试 | 32/32 通过，其中新增 4 个固定包安装／验证／失败／check-only 用例；使用模拟安装过程，不是实际下载全部扩展 |
| Shell / ESM / 发布白名单 / 两个 dry-run | 通过 |
| 固定上游 fresh 源码应用补丁 | 20 个文件哈希匹配；保留一个已知 EOF 空白警告，不改快照源码 |
| 浏览器实际可执行入口 | 固定版本 MCP initialize 握手通过；旧库入口无响应 |
| 修正后完整 13 包实际安装与扩展加载 | **未运行**：收尾时可用内存约 1.5–1.8 GiB，低于本机 2 GiB 资源门槛；不以离线用例冒充完整安装 |
| 另一台真实设备、跨 OS、认证模型、完整 dashboard 重建 | 未验证 |

隔离目录位于同一台 Linux 机器，不等于另一台新机器或另一种操作系统。原安装失败的状态与日志保留，没有因修改脚本而把旧运行改记为成功。

没有启动新的模型任务、登录新网页、连接学校服务器、提交 HPC 作业或重建并部署整套 dashboard。因此核心源码可复用，但**完整安装及无缝迁移仍未通过验收**。补齐缺口应是一项明确的迁移任务，而不是自动扩大到无限 harness 维护。
