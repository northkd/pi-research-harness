# 实时协作：任期、队列、并发与移出

本次改动基于现有 Pi Dashboard 页面和真实后端，不是单独的静态设计稿。
导航、对话、文件、Science、五阶段启动、角色矩阵、费用与权限入口保留。
研究工作台中的完整目标、完成标准、约束和范围之外默认展开；智能体页可以收起这部分，但不删除其内容或改变研究约定。

## 页面入口

| 功能 | 位置与含义 |
|---|---|
| 当前主 Agent | 原主 Agent 选择器；选择提交服务端并建立一个任期，不再以当前标签页或浏览器存储当作绑定依据 |
| 并发设置 | “协作网络”计数旁；修改 Multi / Sub 两个执行上限，收到服务端回执才显示生效 |
| 协作画布 | “会话与下属角色”内；主 Agent 的多个 Multi 是同级分支，Sub 只连实际父会话 |
| 模型与来源 | 卡片直接显示观测到的角色、模型、创建／接入来源；没有证据时写“未记录”，不由任务标题猜测 |
| 待调度队列 | 当前任期画布下、历史任期上；鼠标拖拽或方向键改变同一父计划的队列顺序 |
| 立即开始 | 计划队列卡片；有空位且依赖、权限、资源检查通过就尝试启动，否则优先排队、不抢占 |
| 移出 res-workflow | 主 Agent / Multi 卡片菜单或同面板列表菜单；没有给原生 Subagent 添加独立移出入口 |
| 历史主 Agent | 每个任期独立折叠区；保存当时的标题、模型、来源与父关系，不能借后来角色关系重画历史 |

总览默认 100%；小窗口可以平移、搜索、显式适应画布或全屏，避免为塞进全部卡片而默认缩小成不可读文字。
连线是派发归属，不是任务执行顺序或数据依赖。运行流动效果支持系统“减少动态效果”设置。
队列的模型尚未解析时写“模型待启动确认”，而不是伪称已经调用或自动继承父模型。原生 Subagent 的预配置模型也只是计划值，执行后才以真实注册信息更新。

## 后端是唯一调度依据

持久状态按规范项目目录和操作者范围隔离，保存在 Dashboard 私有的
`res-workflow/collaboration`、`res-workflow/dispatch` 和
`res-workflow/session-reservations` 中。浏览器只读投影并发送带版本号的操作；
localStorage 仅做跨标签页刷新通知，不保存权威主 Agent 或并发数。

### 并发

- 默认每个当前主 Agent 最多 4 个独立 Multi-agent，每个 Multi 最多 3 个执行中的下属。
- 原生 Subagent、直接 `research_session` 和计划分发的子会话，进入同一父会话的共享准入记录，不能分别占 3 个而实际变成 6 个。
- 增加上限触发调度补位；原生候补下一次轮询通常约 1 秒获知。减少上限不杀任务，等已有工作自然结束后再补发。
- 新版本代码和原生插件补丁安装后需要一次正常重启；之后页面调整并发数不需要重启。
- 主机原有独立研究会话总执行上限 8、驻留保护 32、内存准入仍有效。界面从服务端读取可配置范围，目前 Multi 为 1–8，Sub 为 1–32；这些不是研究预算或累计任务数量限制。显式更小的原生工作流本身并发仍可限制该工作流。
- 历史已结束任务不占执行额度；切换前还在执行或状态未知的真实任务仍占物理资源。“历史”标签不是退出证明。

### 排队与立即开始

`research_dispatch plan/delegate` 先落盘完整任务与依赖，再逐项准入；依赖未完成、容量或资源不足时保留候补记录。
拖拽提交完整的同队列 ID 列表和队列 revision；并发修改返回 409，前端刷新后等待用户重新操作，不自动覆盖新顺序。
原生 Subagent 队列也支持按父会话持久排序。拖动不会跨任期、改父关系、重排已经启动的任务或绕过依赖。

“立即开始”不是额外的无限制执行通道。它将选定就绪任务优先推进，并调用与正常队列相同的调度器。
满额回执明确显示“已优先排队”；只有返回启动状态才显示进入启动流程。
失败、取消、恢复待核对或缺少任务的回执，不显示启动成功。

`research_session` 单次直接创建仍是立即创建接口，满额时明确返回 `queued:false`，
指导调用者用 `research_dispatch plan` 提前安排批量工作，不假称失败调用已经入队。
它接受稳定 `requestId`；结果未知时应持同一个 ID 核查，不换 ID 重发同一任务。

### 换主与移出

| 操作 | 当前体系 | 历史、运行与文件 |
|---|---|---|
| 选择另一主会话 | 创建新任期；旧任期待发工作停止继续分发 | 旧下属不自动成为新主的下属；已经运行的工作继续保留 |
| 同一会话再次任主 | 建立新任期，不复用旧任期 ID | 旧任期模型和父关系使用冻结记录 |
| 移出当前主 Agent | 取消绑定；级联实际任期子树及待发队列 | 不自动挑另一主会话；保留原对话、文件、结果与正在执行的进程 |
| 移出某个 Multi | 只移出该任期内有证据的子树 | 其他 Multi、手动接入的同目录会话不受影响 |
| 移出历史角色 | 更新指定历史任期与旧队列 | 同一原会话若又在当前任期担任角色，不移除其当前关联 |

关联移出先保存禁止后续派发的记录，再清理成员标记。部分标记清理失败会在确认框提示，不伪称全部成功。
旧进程的结果回执可按保留的原任务身份归档，但旧主或被移出的会话不能派生新工作。
这些操作不等于停止进程；需要终止正在执行的任务时仍应使用明确的停止操作。

## 重启与首次升级

所有真实创建入口在跨越进程启动边界前保存请求和席位预留。
丢失启动响应、晚注册或重启后的未知进程不会被当作空位，也不会自动再启动一份。
已确认退出的已注册 direct 子会话可以回收额度；`dataUnavailable`、缺心跳或超时本身不是退出证据。
目前不提供绕过核实的“强制释放未知席位”按钮。

旧版主 Agent 选择仅存在于浏览器时，升级不会猜测或虚构历史任期。
首次需要在原选择器明确指定一个主会话；此前旧队列保留但暂不继续派发。
首次选主仅导入能从真实 provenance 确认的旧子树和原计划 ID；来源缺失的同目录会话仍单列。

更新需同时覆盖 Dashboard 源码、研究扩展和认证的 `pi-subagents@0.79.2` 补丁。
不要只 `git pull` 就认为运行中的前后端已更新，也不要手工删除三个私有调度账本。
建议按现有 [0.20 部署流程](RELEASE-0.20.md) 准备新的运行树、保留旧运行树与私有状态备份，
完成测试后再切服务入口和重启。回滚前先停止新调度并核对在跑任务，旧版不认识新的共享预留记录，不能混跑两代调度器。
